# Darwin 动漫社网站使用指南

## 本地查看

网站首页是 `http://127.0.0.1:3000`，创作后台是 `/admin`。本次开发管理员为 `admin@darwin.local`，随机密码保存在项目的 `.data/dev-admin.json`，文件权限为 600；该文件和环境变量不会进入部署镜像。

本地开发也支持通过 `http://localhost:3000` 登录。两个地址的浏览器登录状态分别保存，切换地址后可能需要重新登录。此兼容仅适用于本地开发配置下同协议、同端口的回环地址；生产环境仍只信任配置的正式站点地址。

日常启动在项目目录运行 `pnpm dev`，并保持终端开启。启动器会先检查数据库；使用项目自带的本地数据库时，会按需启动已有数据目录，待数据库可连接后再启动网站。按 Ctrl+C 会停止网站及本次启动的数据库，已有文章和图片会保留。若数据库由另一个进程管理，启动器只复用连接，退出时不关闭它。

`pnpm dev:web` 仅启动网站，适用于自行管理数据库的开发者。若数据库意外断开，正常的 `pnpm dev` 会停止网站并提示检查数据库；修复原因后重新运行即可。

从头启动的依赖安装、数据库迁移和 Docker 命令见根目录 README。初始管理员必须由维护者运行 bootstrap 创建。默认初始化不会公开虚构文章或成员资料，只有显式使用 `--demo` 才导入演示内容。

## 创作与审核

1. 管理员在“账号管理”创建作者或编辑，并单独交付临时密码。成员首次登录必须设置新密码。
2. 在“文章管理”新建文章，填写标题、摘要和可选封面。地址留空会生成唯一标识；也可填写英文短横线地址。
3. 编辑器提供标题、列表、引用、链接、图片、表格、代码和公式。选中图片可修改说明；公式支持行内和独立显示。已有内容可以从修订记录恢复为草稿。
4. 停止输入约 2.5 秒后自动保存。保存提示确认成功后再离开；连接失败时页面会保留当前输入。并发修改会明确报冲突，刷新前请保留尚未保存的文字。
5. 作者提交审核，由编辑或管理员发布或退回修改。修改已发布文章只更新草稿，访客继续阅读上一公开版本，直到“更新发布”。
6. “撤回公开版本”立即停止公开文章，草稿仍保留。回收站支持恢复，永久删除仅限管理员。

RSS、搜索、站点地图与分享信息均读取公开版本。只被草稿引用的图片需要登录且拥有访问权限；内容撤回后，原先公开的媒体若没有其他公开引用，也恢复为私密。

## 静态页面与成员

“静态页面”可组合富文本、图文、画廊、成员集合和链接列表。用模块右上角箭头调整顺序。成员集合不选特定成员时显示全部成员。

“主要成员”管理公开简介、头像、兴趣、链接和排序数字。此处的成员资料与后台账号相互独立；删除公开资料不影响登录账号。较小的排序数字显示在前。

## 特殊页面

“特殊页面”单独管理 `/privacy`（隐私政策）和 `/about`（关于社团）。管理员和编辑可以编辑简介、富文本及图片，先保存草稿，再发布。保存草稿不会更改公开版本；并发编辑会提示冲突。两页的固定地址和页尾入口不会因内容修改而变化，原有 `/pages/*` 静态页面仍然保留。

首次安装提供基础说明。启用订阅和入社申请前，请在隐私政策中补充社团实际的联系渠道、资料保留与删除安排，并检查关于社团的介绍。

## 邮件、订阅与入社申请

管理员在“邮件设置”填写 SMTP 服务器、端口、TLS 或 STARTTLS、用户名、邮箱授权码和发件邮箱，保存后向自己的邮箱发送测试邮件。授权码不会回显，留空保留原值；需要移除时显式选择清除。申请收件邮箱用于接收入社申请。具体配置及升级命令见 [SMTP 配置](SMTP配置.md)。

两个推送开关相互独立：

- **自动推送**：新文章首次发布时，向已确认的订阅者发送摘要和原文链接。保存草稿、修改重发不会重复推送。
- **手动推送**：管理员和编辑在“订阅与入社”选择已发布文章，预览接收人数，再确认发送。同一篇文章不会重复发送给同一位订阅者。

访客从页尾进入“邮件订阅”，提交邮箱并在确认邮件中完成确认后才会收到推送。邮件里的退订链接打开确认页，点击确认后停止后续推送。退订及撤回文章会取消尚未发送的相关推送，已经送达的邮件无法撤回。

“申请入社”提供姓名 / 称呼、邮箱、兴趣方向、自我介绍四项。申请人确认邮箱后，申请表才进入可审核状态，同时发送一份副本给申请人和配置的社团收件邮箱。申请不会自动成为公开成员资料或登录账号，也不会自动订阅刊物。管理员和编辑可以审核申请，管理员可以删除申请资料或移除订阅者。

“邮件设置”下方显示发送记录。临时故障会自动重试，最终失败的邮件可由管理员重新加入队列；SMTP 停用时暂停发信。后台页面中的成功提示表示申请或邮件任务已保存，邮件实际送达情况以发送记录和收件箱为准。

## 导航与站点信息

管理员在“站点设置 → 访问域名”填写主要访问地址，或点击“使用当前地址”自动填入。
域名可以不带协议，此时按 HTTPS 保存；完整地址需包含协议和实际端口，不包含路径。
如同时使用带 www 的地址或保留迁移前的域名，可在“其他允许登录的地址”中每行填写一个。
保存后立即生效，主要地址同时用于分享链接、RSS、robots 与 sitemap。

主要地址留空时继承服务器配置；“服务器保留入口”始终允许登录，方便修复误填。
新地址必须已经完成域名解析、反向代理与 HTTPS 配置，切换地址后需重新登录。
首次部署尚未登录时，先按[域名配置与部署](域名配置与部署.md)配置服务器的三个域名变量。

管理员在“站点设置”维护名称、完整标语、简介和页尾文字。首页与主要成员是固定且始终可见的入口。其他导航可改名、排序、隐藏、删除，并支持站内路径及 HTTPS 外链。

页尾始终提供新的“关于社团”和“隐私政策”入口。如需在顶部展示“关于社团”，可在站点导航中添加 `/about`；旧导航不会被自动覆盖。

## 媒体与账号

媒体库接受实际格式经过验证的 JPG、PNG、WebP、AVIF，单文件最多 12 MB。应用会重新编码图片并检查尺寸。仍被草稿、修订、公开内容或成员引用的文件不可删除。

停用账号、重置密码和修改密码会撤销旧会话。系统始终保留至少一位可用管理员。SMTP 当前用于订阅和申请邮件，后台账号的密码找回仍由管理员处理。

## 维护

发布前执行类型检查、lint、测试与生产构建。Docker 备份会短暂停止应用，以取得数据库与媒体的一致快照。恢复前验证归档，再切换数据库和媒体；旧数据留作回滚。具体命令与验收记录见 README 和 `docs/qa/`。
