# 九周年站点版本切换

站点外观由服务端环境变量 `SITE_EDITION` 决定，可选值只有：

| 值              | 含义                                           |
| --------------- | ---------------------------------------------- |
| `anniversary-9` | 九周年版本 |
| `classic`       | 原有经典版本                                   |

值会先去掉首尾空白；变量缺失、为空或无效时回退到所在分支的默认版本：
`main` 为 `classic`，`9th-Anniversary` 为 `anniversary-9`。已有 `.env` 中
显式设置的值优先于分支默认值，因此切换分支时也应检查部署配置。
这个开关只决定站点的可见外观，不会修改文章、成员、
账户、数据库或媒体文件。

## 本地切换

在项目根目录运行：

```bash
pnpm site:edition classic
pnpm site:edition anniversary-9
```

命令只会更新忽略提交的 `.env.local` 中的 `SITE_EDITION`：保留其余环境
变量、注释、引号、行尾格式和现有文件内容，不会打印现有配置或秘密；终端
只确认所选择的公开版本值，并将文件权限设置为 `0600`。无效参数会在写入前
失败：

```bash
pnpm site:edition --help
```

Next.js 16.3.5 的 `next dev` 会监听 `.env.local` 并重载环境配置，因此常规
`pnpm dev` 或 `pnpm dev:web` 运行时，命令完成后刷新首页即可看到版本切换，
不需要手动重启开发服务器。若以
`SITE_EDITION=... pnpm dev` 这种方式在 shell 中显式设置过变量，shell 环境
优先于 `.env.local`；请移除该 shell 变量后重新启动开发服务器。

## 生产切换

生产环境使用部署目录的 `.env`，而不是本地开发用的 `.env.local`。在 `.env`
中添加或修改：

```dotenv
SITE_EDITION=classic
```

随后重新创建应用容器以把新的运行时环境交给 Node 进程：

```bash
docker compose up -d --no-deps --force-recreate app
```

前提是已部署同时包含 `classic` 与 `anniversary-9` 两套实现的新版镜像；旧镜像
没有九周年代码，不能只改环境变量得到九周年版。满足这个前提时，这一步不需要
重新构建镜像。单独执行 `docker compose restart app` 会重启已有容器，但不会用
修改后的 Compose `.env` 重新创建容器环境，因此不能用于这项切换。非 Docker
部署也应先更新服务管理器中的环境变量，再重启应用进程。

## 回退范围

| 操作            | 影响范围                   | 适用情况                                                                                                                                                                        |
| --------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 版本开关        | 仅可见外观                 | 从九周年版快速回到经典版，优先使用 `pnpm site:edition classic` 或生产环境变量切换                                                                                               |
| 源码回退        | 代码、配置、公共资源和文档 | 在独立目录检出经验证的分支或提交，构建后重新部署；不覆盖运行中实例的配置和上传目录 |
| 数据库/媒体恢复 | 内容数据库与上传媒体       | 只有内容或账号也需要回到历史快照时，才依照 [README 的备份恢复流程](../README.md#backup-and-restore)处理；外观切换不恢复数据 |

源码回退和数据库恢复彼此独立：恢复源码不会自动恢复内容数据，恢复数据库也
不会撤销新首屏的代码。执行数据库或媒体恢复前，先验证归档并在隔离环境恢复演练。
开发期的私有归档保存在本地 `backups/`，不随 Git 仓库发布。
