# 本地开发启动恢复验证

## 问题与原因

用户访问首页时，读取 `settings` 的服务端查询因 `ECONNREFUSED 127.0.0.1:55432` 失败。检查时 Next.js 仍监听 3000，但本地 PostgreSQL 没有监听 55432。原先的 `pnpm dev` 只启动 Next.js，数据库依赖独立的前台进程。

恢复现有 `.data/postgres` 后，首页和 `/api/health` 返回 200，原有 4 篇文章、3 位成员和 1 个媒体记录仍存在。恢复过程中没有重新初始化、迁移、重置或导入示例内容。

## 修复

`pnpm dev` 统一检查数据库就绪状态后再启动 Next.js。仅项目约定的本地数据库允许按需启动，其他 `DATABASE_URL` 继续使用已有配置。退出时只关闭本次启动的数据库；复用的数据库由原进程继续管理。数据库失活会停止网站并报告失败。`pnpm dev:web` 保留单独启动 Next.js 的能力。

## 浏览器复测

Chrome 和 WebKit 均检查首页、文章跳转、成员页及返回首页，且确认封面图片已加载。两个浏览器的 `pageerror` 均为空，用户报告的数据库查询错误和 `performance.measure` TypeError 均未再出现。此结果不把后一个错误单独认定为已定位的框架缺陷。

结果见 `browser-results.json`，截图见 `home-chrome.png` 和 `home-webkit.png`。截图由主智能体检查。

## 启动器验证

实际进程测试已通过，结果见 `lifecycle-results.json`：

- 从关闭状态启动现有数据库，SQL 就绪后启动网站，首页返回 200。
- 向启动器发送 Ctrl+C 信号后，本次启动的网站及数据库均停止监听。
- 复用独立启动的数据库时，启动器退出只关闭网站，数据库仍可用。
- 主动停止本次数据库后，启动器检测到失活、关闭网站并以非零状态退出。
- 测试前后的 `.env.local` SHA-256 相同，配置未被改写。

类型检查和 ESLint 通过；5 个 Vitest 文件、28 项测试通过，其中 9 项覆盖开发启动器与配置边界。集成测试结束后再次确认原有 4 篇文章、3 位成员和 1 个媒体记录保留。

本次预览通过 `pnpm dev` 作为独立后台进程启动，确认父进程为系统进程，而非临时工具会话。进程号和私有日志分别保存在忽略目录下的 `.data/dev-preview.pid`、`.data/dev-preview.log`。这是本次本地预览的运行方式；日常手动启动仍使用 `pnpm dev` 并保持终端开启。

本次改动限于本地开发启动与说明文档，未修改页面视觉、公开内容、数据库结构或 Docker 生产部署配置。
