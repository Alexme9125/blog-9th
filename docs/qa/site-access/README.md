# 站点访问域名验收

2026-09-22 完成。管理员设置页增加主要访问地址、“使用当前地址”按钮、额外登录地址和已生效地址反馈，沿用现有后台视觉。

## 行为与权限

- 独立保存 `site_access` 设置，不覆盖社团信息、导航或成员介绍。仅管理员可读取和修改，保存与操作日志在同一事务中完成。
- 输入规范化为精确来源，接受裸域名并默认 HTTPS；拒绝通配符、登录凭据、路径、查询、片段及非法主机名。生产仅 HTTPS，开发 HTTP 仅回环地址。
- Better Auth 在每个 HTTP 请求读取数据库允许列表。初始化不把数据库域名固化进单例，新增、删除无需重启。部署环境中的认证地址始终保留为恢复入口。
- 请求 Host 不会自动加入允许列表。生产环境认证 URL 本身也接受严格校验；拒绝另设 `BETTER_AUTH_TRUSTED_ORIGINS`，保持单一额外地址来源。
- 客户端认证同源，Cookie 保持 host-only；新地址需要独立登录。公共页面 metadataBase、文章 canonical、RSS、sitemap、robots 使用当前主地址，空配置继承环境地址。

## 验证结果

- 10 个文件、69 项测试通过，包括真实 HTTP 认证处理器的域名增删（同一处理器实例中，删除后立即 403）、保留环境入口、伪造来源拒绝、管理员权限和数据库故障传播。
- CLI 的 9 项测试验证三项环境变量同步更新、其余内容保留、原子写入与 0600 权限、无效 URL/非普通文件/多行歧义输入拒绝。测试只操作临时环境文件，未改真实部署 `.env`。
- Chrome、WebKit 均实际登录并保存当前访问地址，刷新后持久化；错误通配符被拒绝，canonical、RSS、sitemap 和 robots 使用已保存地址。测试结束已恢复先前的访问配置。
- 两个浏览器在 1440、768、390、360px 无横向溢出和运行错误；主智能体复核截图。见 [自动结果](results.json)、[桌面设置](chrome-settings-1440.png)、[手机设置](chrome-settings-390.png)。
- 类型检查与 lint 通过；以不可连接的数据库 URL 和空认证密钥运行生产构建仍成功，确认构建不依赖首次部署的运行时数据库和认证配置。
- 构建保留现有媒体模块两项动态文件系统追踪警告。本轮没有变更该模块，未执行公网部署或重建 Docker 运行中的应用镜像。

首次部署、域名变更和失去登录入口时的恢复步骤见[域名配置与部署](../../域名配置与部署.md)。
