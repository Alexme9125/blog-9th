# 本地后台登录来源修复

2026-09-22：用户在 `http://localhost:3000` 登录时收到“邮箱或密码不正确，或此账号已停用”。

## 原因与修改

运行日志记录 `Invalid origin: http://localhost:3000`，登录接口返回 403。服务端配置的认证地址为 `http://127.0.0.1:3000`，此前仅信任该地址；前端将这一来源拒绝误报为凭据错误。只读检查确认本地管理员存在、未停用，保存的凭据与数据库匹配。本次没有修改密码、账号角色或停用状态。

`trustedAuthOrigins` 仅在非生产、配置主机为回环地址时允许 `localhost`、`127.0.0.1`、`[::1]` 的同协议、同端口精确来源。生产和远程开发配置只返回配置地址本身。未关闭来源校验或 CSRF 防护，未加入通配域名。登录错误提示按具体来源错误码与凭据错误区分。

## 验证

- Chrome 与 WebKit 分别在 `localhost:3000`、`127.0.0.1:3000` 使用现有凭据成功登录，接口返回 200；到达工作台，刷新后会话仍有效。
- cookie 为当前主机专用且带 HttpOnly；两个地址无需跨域传递凭据。
- 四组验证中，未授权外部来源均被拒绝（403 / `INVALID_ORIGIN`）。退出返回 200，随后访问后台跳回登录页。浏览器运行错误为零。
- 真实错误密码返回 401，继续显示不区分账号是否存在或停用的凭据提示；浏览器模拟的来源拒绝响应显示独立的地址配置提示。
- 8 个测试文件、44 项测试通过，类型检查、lint、生产构建通过。生产构建保留原有媒体模块的两条动态文件系统追踪警告，与本次认证变更无关。
